# 可行性报告：G-Helper → macOS

## 一句话结论

**G-Helper 不能"移植"到 macOS，只能"重写"；大部分灯光功能可以落地，路径已经打通。**
能落地的部分：**笔记本内置键盘灯**（部分机型，rogauracore 协议，已内置支持）、USB HID 外设灯光、
温度/转速读取、完整灯效引擎与 App 形态。
不能落地的部分：走 ACPI-WMI 的**灯条/Logo 灯**（仅远程桥可达）、AniMe Matrix、风扇曲线、功耗模式。

> 修订：初版报告断言"内置键盘背光在 macOS 上物理不可达"，经 [`macRogAuraCore`](https://github.com/black-dragon74/macRogAuraCore)
> 证实不准确——不少 ROG 机型把内置键盘的 Aura 控制器暴露成 USB HID 接口（见协议笔记 2.4 节），
> 这部分机型在 macOS 上可直接控制。是否可达以 `aura-probe devices` 枚举结果为准。

## 1. G-Helper 是什么技术栈

| 项目 | 实际情况 |
|---|---|
| 语言 | C# / .NET 8 |
| UI | WinForms（Win32 原生控件，非 XAML） |
| 体积 | 单 exe，不写注册表服务 |
| 仓库文件 | 约 180 个 `.cs` 文件，机器相关逻辑集中在 `AsusACPI.cs` |
| 硬件通信 | ① `\\.\ATKACPI` 设备句柄 + `DeviceIoControl`<br>② `root\wmi` 命名空间下的 `AsusAtkWmi_WMNB`（`DeviceSet` / `DeviceGet`）<br>③ 外设走 USB HID |
| 依赖 | `Asus System Control Interface` 驱动（Armoury Crate 那套） |

WinForms 没有 macOS 对应物（AppKit/SwiftUI 是完全不同的模型），C# 逻辑也无法跨语言直接复用。
所以"移植"这个词在这里只对**语义**成立：功能定义可以照搬，代码必须重写。

## 2. 为什么笔记本灯光在 macOS 上做不到

G-Helper 设置键盘灯时的真实代码（`AsusACPI.cs`）：

```csharp
public const int TUF_KB  = 0x00100056;
public const int TUF_KB2 = 0x0010005a;
public const int TUF_KB_BRIGHTNESS = 0x00050021;

public void TUFKeyboardBrightness(int brightness, string log = "TUF Backlight")
{
    int param = 0x80 | (brightness & 0x7F);
    DeviceSet(TUF_KB_BRIGHTNESS, param, log);
}

public void TUFKeyboardRGB(AuraMode mode, Color color, int speed, string? log = "TUF RGB")
{
    byte[] setting = new byte[6];
    setting[0] = (byte)0xb4;        // 命令
    setting[1] = (byte)mode;        // 灯效模式码
    setting[2] = color.R;           // R
    setting[3] = color.G;           // G
    setting[4] = color.B;           // B
    setting[5] = (byte)speed;       // 速度
    int result = DeviceSet(TUF_KB, setting, log);
    ...
}
```

`DeviceSet` 最终落到两条 Windows 专属通道：

- `\\.\ATKACPI`：一个由 ASUS 驱动创建的设备对象，靠 `DeviceIoControl` 收发；
- `AsusAtkWmi_WMNB`：一个 **ACPI-WMI** 映射方法，由 BIOS 里的 ASL 提供，Windows 的 `AcpiWmi` 驱动负责翻译。

macOS 这两条都没有：

| 层 | Windows | macOS (XNU) |
|---|---|---|
| ACPI 解析 | ACPICA + `AcpiWmi` 驱动 | 有自己的 ACPI 解释器，但**不导出 WMI 映射** |
| 厂商设备对象 | ASUS 驱动建 `\\.\ATKACPI` | 无对应物 |
| 内核扩展 | WDM/KMDF | 需要 kext，Apple Silicon **完全禁止**第三方 kext |
| 用户态驱动 | — | DriverKit 只支持 USB / PCIe / Serial / NIC / Audio / BlockStorage 等，**不支持 ACPI** |

结论：**同一台 ASUS 笔记本跑 macOS，没有任何一层能碰到 EC 里的灯光寄存器。**
这不是"还没人做"，而是"系统不提供这条路径"。同理，风扇曲线、功耗模式、GPU 模式、屏幕刷新率切换、电池限充，全部属于同一类。

> 顺带排除两个常见幻想：
> - Hackintosh 上装 ASUS 驱动？XNU 没有 WMI 栈，驱动无处落脚。
> - 写个 kext 直接怼 EC？Apple Silicon 不允许；Intel 机型需关 SIP，且要自己实现整套 ACPI EC 访问，风险极高、不可分发。

## 3. macOS 上真正能做的

### 3.1 能，而且效果好

| 能力 | 通道 | 说明 |
|---|---|---|
| 外置 ROG 键盘 / 鼠标 / 灯控盒的 RGB | USB HID（IOHIDDevice） | macOS 原生支持厂商自定义报告，和 OpenRGB 走的是同一条路 |
| 温度 | AppleSMC（只读） | Intel Mac 键位齐全；Apple Silicon 需按机型探测键名 |
| 风扇转速 | AppleSMC（只读） | 无风扇机型会返回空 |
| 灯效引擎 | App 内计算 | 逐帧算色，不依赖固件支持，效果上限比固件模式更高 |
| 预设 / 配色管理 | 本地 JSON | 随便存多少套 |

### 3.2 有条件能做

| 能力 | 条件 |
|---|---|
| 笔记本内置键盘灯 | **直接可用**（部分机型）：Aura 控制器暴露为 USB HID，内置 rogauracore 协议包；不在已知 PID 列表的机型用 `aura-probe` 枚举后加 PID |
| 笔记本灯条 / Logo 灯 | 需要一台能跑 ACPI-WMI 的机器做 **远程桥 agent**（Windows 或 Linux + asus-wmi 内核模块）。Mac 端只做 UI 与协议渲染，帧通过 HTTP 发过去 |
| 新机型协议适配 | 需要真机 + `aura-probe` 抓包校准，改 JSON 协议包即可，不用改代码 |

### 3.3 做不到

风扇曲线写入、功耗模式（Silent/Balanced/Turbo）、GPU Mux 切换、屏幕刷新率与 OD、AniMe Matrix、电池限充、XG Mobile、BIOS/驱动更新。
原因同上：全部走 ACPI-WMI 或厂商驱动。

## 5. 如果目标就是"用 Mac 控制那台 ASUS 笔记本"

只有一条现实路径，本项目已经预留：

```
[ macOS App ]  --HTTP JSON-->  [ agent：Windows / Linux ]
   UI + 灯效引擎                  AsusACPI.DeviceSet(...)
   协议包渲染                      ↓
                               ACPI-WMI → EC → 灯
```

- Mac 端：`RemoteBridgeTransport`，已实现，接口见 `docs/03-硬件协议笔记.md`。
- agent 端：Windows 上可以直接复用 G-Helper 的 `AsusACPI`；Linux 上走 `asus-wmi` / `asus_armoury` sysfs。agent 不在本仓库范围内。

如果那台机器**就是**这台 Mac（ASUS 机身 + macOS），则此路不通——Mac 与 ASUS 硬件不存在可用的通信层。

---

## 6. 结论与建议

1. 把项目定位成 **"macOS 原生 Aura 控制台 + 灯效引擎"**，而不是"G-Helper 的 mac 版"。前者诚实、可持续；后者注定在第一次点"应用"时露馅。
2. 后台按**传输层可替换**设计（已落地）：HID / 远程桥 / 演示，三者同一套协议与引擎。
3. UI 不要仿 WinForms。用 macOS 的菜单栏常驻 + 单窗口深色/浅色自适应，粉色作为品牌色而非满屏粉。
4. 真机适配阶段唯一需要投入的是**协议包校准**，这件事已经做成 JSON，不需要改 Swift 代码。
